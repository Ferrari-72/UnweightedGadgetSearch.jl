## 🎯 核心理解

### 映射算法的本质

**一句话总结**：
> 每个顶点通过 copy line 连接到相邻顶点，当连接需要"跨过"其他顶点时（交叉），用 gadget 替换，并在网格上分散开避免直接交叉。

---

## 📐 完整映射流程（4个步骤）

### 步骤 1：路径分解（Path Decomposition）

**做什么**：给顶点排个顺序，让网格尽量"窄"（高度小）

**为什么**：
- 网格高度 = pathwidth + 1
- pathwidth 越小，网格越窄，转换后的图越小

**类比**：像整理书架，按顺序放书，让书架尽量窄。

---

### 步骤 2：创建交叉格（Crossing Lattice）

**做什么**：
- 每个顶点 → 变成 T 形的 **copy line**（复制线）
- 每条边 → 标记在哪里**交叉**

**为什么 T 形**：
- **垂直部分**：连接上下的顶点
- **水平部分**：让边可以"交叉"

**例子**：
```
原图：          网格上：
1───2          1  2  3  (每个顶点变成T形)
│   │          │  │  │
3───4          ├──┤  │  (水平部分用于交叉)
```

---

### 步骤 3：应用交叉组件（Apply Crossing Gadgets）

**做什么**：
- 扫描网格，找到"交叉"、"转弯"等模式
- 用预计算好的 gadget（BATOIDEA、Turn 等）替换它们
- **记录**每次替换（为了之后反推解）

**过程**：
```
看到交叉 → 用 BATOIDEA 替换
看到转弯 → 用 Turn 替换
看到分支 → 用 Branch 替换
...
```

---

### 步骤 4：应用简化器（Apply Simplifiers）

**做什么**：删除不必要的顶点（比如"悬挂的腿"）

**目的**：让图更小，计算更快

---

## 🔄 映射（Mapping）和反向映射（Back-Mapping）

### 映射（Mapping）：原图 → King's 子图

**意思**：把原图 G 转换成 King's 子图 G'

```
原图 G（任意结构）
    │
    │ 映射过程：
    │ - 路径分解
    │ - 创建 copy lines
    │ - 应用 gadgets
    │
    ▼
King's 子图 G'（网格结构）
```

**映射记录了什么？**
- 每次用了哪个 gadget
- 用在哪里（位置）
- 总 overhead（MIS 变化了多少）

**代码中**：
```julia
result = map_graph(g)  # 映射
# result.mapping_history 记录了所有替换
# result.mis_overhead 记录了总误差
```

---

### 反向映射（Back-Mapping）：King's 子图 → 原图

**意思**：把 King's 子图上的解转回原图

```
在 G' 上求 MIS → 得到解 S'
    │
    │ 反向映射：
    │ - 反向应用每个 gadget
    │ - 用记录的映射历史
    │
    ▼
原图 G 的解 S
```

**怎么反向映射？**

**步骤 1**：在 G' 上求解
```julia
solution_G' = solve_MIS(G')  # 得到 King's 子图的解
```

**步骤 2**：反向应用 gadgets（逆序）
```julia
# 从最后一个 gadget 开始，倒着来
for gadget in reverse(mapping_history):
    # 把 gadget 替换回原来的模式
    # 同时把解也转回去
    solution = unapply_gadget(gadget, solution)
```

**步骤 3**：从 copy lines 提取原图解
```julia
# 每个 copy line 代表原图的一个顶点
# 提取 copy line 的值
original_solution = extract_from_copylines(solution)
```

**步骤 4**：修正 MIS 大小
```julia
MIS(G) = MIS(G') - mis_overhead
```

## 📊 复杂度分析

### 大小复杂度（Size Complexity）

**定理**：
```
|V_mapped| = O(|V| × pw(G))
```

**意思**：
- 转换后的图大小 = 原图顶点数 × 路径宽度
- 最多是**二次增长**

**为什么？**

**分解**：
1. **Copy lines**：每个原图顶点变成一条 copy line
   - Copy line 长度 ≈ O(pw(G))
   - 所以 copy lines 总大小 = |V| × O(pw(G))

2. **Gadgets**：每个交叉/转弯用 gadget 替换
   - 每个 gadget 是常数大小（比如 BATOIDEA 是 11 个顶点）
   - 最多有 O(|V|²) 个交叉（每对顶点可能交叉）
   - 但实际中，交叉数量受 pathwidth 限制

**总大小**：
```
|V_mapped| = |V| × O(pw(G)) + O(|V|²) × 常数
           = O(|V| × pw(G))  （如果 pw(G) ≥ 常数）
```

---

### 时间复杂度（Time Complexity）

**映射过程**：
```
1. 路径分解：O(2^pw(G) × |V|) 或更快（贪心）
2. 创建 copy lines：O(|V| × pw(G))
3. 应用 gadgets：O(|V|²) （扫描网格）
4. 简化：O(|V|²) （多次扫描）

总时间：多项式时间（polynomial）
```

**求解**：
```
在 G' 上求 MIS：
- 经典算法：O(2^|V'|) = O(2^(|V|×pw(G)))
- 量子算法：可能更快
```

**反向映射**：
```
O(|V|²) （反向应用所有 gadgets）
```

---

### 最优性（Optimality）

**定理**：这个复杂度是**最优的**（在 ETH 假设下）

**证明思路**：
1. **ETH**（指数时间假设）：一般图的 MIS 不能在 2^o(n) 时间内求解
2. **King's 图**：可以在 2^O(pw) 时间内求解
3. **如果**转换后大小是 o(|V| × pw(G))（比 O(|V| × pw(G)) 更小）
4. **那么**我们可以用 King's 图算法在 2^o(n) 时间内求解一般图
5. **矛盾**！所以转换大小必须是 Ω(|V| × pw(G))

**结论**：O(|V| × pw(G)) 是**最优的**（最多差一个常数因子）

## 📋 完整例子

### 原图（5个顶点）：
```
1───2
│   │
3───4───5
```

### 映射过程：

**步骤 1**：路径分解 → 顺序 [1, 2, 3, 4, 5]，pathwidth = 2

**步骤 2**：创建 copy lines
```
每个顶点变成 T 形：
- 顶点1：列1，行2（hslot）
- 顶点2：列2，行2
- 顶点3：列3，行2
- 顶点4：列4，行2
- 顶点5：列5，行2
```

**步骤 3**：标记交叉
```
边 1-2：在列1和列2的水平部分交叉
边 2-4：在列2和列4的水平部分交叉
边 3-4：在列3和列4的水平部分交叉
边 4-5：在列4和列5的水平部分交叉
```

**步骤 4**：应用 gadgets
```
每个交叉用 BATOIDEA 替换
```

**步骤 5**：简化
```
删除不必要的顶点
```

### 反向映射过程：

**步骤 1**：在 G' 上求解 MIS → 得到解 S'

**步骤 2**：反向应用 gadgets（从最后一个开始）
```
unapply_gadget(最后一个gadget, S')
unapply_gadget(倒数第二个gadget, S')
...
```

**步骤 3**：从 copy lines 提取
```
每个 copy line 的值 → 原图对应顶点的值
```

**步骤 4**：修正
```
MIS(G) = MIS(G') - mis_overhead
```

## ✅ 关键理解总结

| 概念 | 我的理解 |
|------|----------|
| **映射** | 把原图 G 转换成 King's 子图 G'，记录所有替换 |
| **反向映射** | 把 G' 上的解转回 G，通过反向应用 gadgets |
| **Copy line** | 原图的一个顶点在网格上变成 T 形线，连接相邻顶点 |
| **Gadget 替换** | 当连接需要"跨过"其他顶点时，用 gadget 替换 |
| **大小复杂度** | O(\|V\| × pw(G)) - 二次增长，最优 |
| **时间复杂度** | 映射是多项式时间，求解是指数时间（但 pw 通常小） |
| **最优性** | 在 ETH 假设下，这个复杂度是最优的 |

## 🔑 核心思想

**映射算法的本质**：
> 每个顶点通过 copy line 连接到相邻顶点，当连接需要"跨过"其他顶点时（交叉），用 gadget 替换，并在网格上分散开避免直接交叉。

**为什么需要映射**：
> 因为量子计算机只能处理 King's 子图，所以要把任意图"翻译"成 King's 子图。

**为什么能反向映射**：
> 因为记录了每次替换（mapping_history），而且每次替换的 α-tensor 关系已知，所以可以反向应用。
