# About 3-SAT

本笔记讨论两个核心问题：
1. 为什么 2-SAT 是 P 的，但 3-SAT 是 NP-complete 的？
2. 3-SAT 的复杂度如何分析？

---

## 📖 问题定义

```
2-SAT: 每个子句最多 2 个文字
  例：(x₁ ∨ x₂) ∧ (¬x₁ ∨ x₃) ∧ (¬x₂ ∨ ¬x₃)

3-SAT: 每个子句恰好 3 个文字
  例：(x₁ ∨ x₂ ∨ x₃) ∧ (¬x₁ ∨ x₂ ∨ ¬x₄)
```

---

## 🔑 Part 1: 为什么 2-SAT 是 P 的？

### 核心洞察：2-SAT 可以转化为图问题！

每个 2 文字子句 $(a \vee b)$ 等价于两个**蕴含关系**：

$$a \vee b \equiv (\neg a \Rightarrow b) \land (\neg b \Rightarrow a)$$

```
(x ∨ y) 的意思是：
  "如果 x 是假的，那 y 必须是真的"
  "如果 y 是假的，那 x 必须是真的"
```

### 🏗️ 构建蕴含图

```
对于公式：(x₁ ∨ x₂) ∧ (¬x₁ ∨ x₃) ∧ (¬x₂ ∨ ¬x₃)

转化为蕴含：
  (x₁ ∨ x₂)   →  ¬x₁ → x₂,  ¬x₂ → x₁
  (¬x₁ ∨ x₃) →   x₁ → x₃,  ¬x₃ → ¬x₁
  (¬x₂ ∨ ¬x₃)→   x₂ → ¬x₃,  x₃ → ¬x₂

构建图：
  节点：x₁, ¬x₁, x₂, ¬x₂, x₃, ¬x₃
  边：每个蕴含关系
```

### ✅ 关键定理

```
┌─────────────────────────────────────────────────────┐
│  2-SAT 公式可满足  ⟺  对于任何变量 x，              │
│                       x 和 ¬x 不在同一个强连通分量中  │
└─────────────────────────────────────────────────────┘
```

**算法**：
1. 构建蕴含图 — O(n + m)
2. 求强连通分量 (SCC) — O(n + m)，用 Tarjan 或 Kosaraju 算法
3. 检查是否有 x 和 ¬x 在同一 SCC — O(n)

**总时间：O(n + m) — 多项式时间！**

---

## ❌ Part 2: 为什么 3-SAT 不能用同样方法？

### 问题：3 个文字的蕴含太复杂了！

```
2 文字子句 (a ∨ b)：
  ¬a → b  （一对一的蕴含）
  简单！可以用图表示

3 文字子句 (a ∨ b ∨ c)：
  ¬a → (b ∨ c)  （一对多的蕴含！）
  
  "如果 a 是假的，那么 b 或 c 至少一个是真的"
  → 但不知道具体是哪个！
  → 需要做选择！
  → 选择 = 指数级分支！
```

### 📊 直观对比

```
2-SAT：决策像"推导"
─────────────────────────────
  设 x₁ = T
    → 由 (¬x₁ ∨ x₃)，得 x₃ = T
    → 由 (¬x₃ ∨ x₄)，得 x₄ = T
    → ...
  一路推导下去，没有分支！
  
  
3-SAT：决策像"猜测"
─────────────────────────────
  设 x₁ = T
    → 由 (¬x₁ ∨ x₂ ∨ x₃)，得 x₂ = T 或 x₃ = T
    → 选哪个？
        ├── 选 x₂ = T → ...
        └── 选 x₃ = T → ...
    → 分支！可能要回溯！
```

### 🎨 图解对比

```
2-SAT 的决策树：                3-SAT 的决策树：
      
      │                              │
      ▼                              ▼
    一条路                    ┌──────┼──────┐
      │                       ▼      ▼      ▼
      ▼                      分支   分支   分支
    一条路                    │      │      │
      │                      ...    ...    ...
      ▼                       
    解！                     指数级分支！
    
  O(n) 时间                  O(2ⁿ) 最坏情况
```

### 🧮 数学上的区别

| 特性 | 2-SAT | 3-SAT |
|-----|-------|-------|
| 每子句文字数 | 2 | 3 |
| 蕴含结构 | 一对一 | 一对多（析取） |
| 传播确定性 | ✅ 确定性传播 | ❌ 需要猜测 |
| 图结构 | 简单有向图 | 超图/复杂结构 |
| 最佳算法 | O(n+m) | O(2^n) 最坏 |
| 复杂度类 | **P** | **NP-complete** |

---

## 🌡️ "相变"现象

从 k=2 到 k=3，只增加了一个文字，但问题从"容易"跳变到"极难"！

```
k-SAT 的复杂度随 k 变化：

  k = 1: 1-SAT  → 平凡（O(n)检查）
  k = 2: 2-SAT  → P（多项式可解）
  ─────────────── 相变点！───────────────
  k = 3: 3-SAT  → NP-complete！
  k = 4: 4-SAT  → NP-complete
  k = 5: 5-SAT  → NP-complete
  ...
```

## 📊 Part 3: 3-SAT 复杂度分析

### 输入规模

```
3-SAT 实例：
  n = 变量数量（x₁, x₂, ..., xₙ）
  m = 子句数量
  
每个子句有 3 个文字，所以输入大小 ≈ O(m) 或 O(n + m)
```

### 暴力算法

```python
def brute_force_3sat(formula, n):
    # 枚举所有可能的赋值
    for assignment in all_assignments(n):  # 2ⁿ 种
        if satisfies(formula, assignment): # O(m) 检查
            return True
    return False
```

```
时间复杂度：O(2ⁿ × m)
            ↑     ↑
          枚举  每次验证

空间复杂度：O(n + m)
```

### 为什么是 NP-complete

```
┌─────────────────────────────────────────────────────┐
│  3-SAT 在 NP 中：                                   │
│    证据：一个赋值（n 个 0/1）                        │
│    验证：检查每个子句是否满足 — O(m) 时间            │
│                                                     │
│  3-SAT 是 NP-hard：                                 │
│    Cook-Levin 定理证明任何 NP 问题都能归约到 SAT     │
│    然后 SAT 可以简单转化为 3-SAT                    │
└─────────────────────────────────────────────────────┘
```

### 目前最好的算法

| 算法 | 时间复杂度 | 年份 |
|-----|----------|------|
| 暴力枚举 | O(2ⁿ) | — |
| DPLL | O(2ⁿ) 最坏，实践中快 | 1962 |
| Schöning 随机算法 | O(1.334ⁿ) | 1999 |
| PPSZ 算法 | O(1.308ⁿ) | 2005 |
| 目前最好 | **O(1.307ⁿ)** | ~2020 |

```
改进看起来小，但实际影响巨大：

  n = 100 时：
    2ⁿ     = 2¹⁰⁰     ≈ 10³⁰
    1.307ⁿ = 1.307¹⁰⁰ ≈ 10¹²
    
  差了 10¹⁸ 倍！
```

### 验证 vs 求解

```
┌────────────────────────────────────────────┐
│           验证（给定赋值）                   │
│  ──────────────────────────────────────    │
│  遍历每个子句，检查是否至少一个文字为真       │
│                                            │
│  时间：O(m)  ← 多项式！所以在 NP 中         │
└────────────────────────────────────────────┘

┌────────────────────────────────────────────┐
│           求解（找赋值）                     │
│  ──────────────────────────────────────    │
│  最坏情况要尝试所有 2ⁿ 种赋值                │
│                                            │
│  时间：O(2ⁿ)  ← 指数级！                   │
└────────────────────────────────────────────┘
```

```

         │                           ╱
         │                        ╱
         │                     ╱

```

## 🎯 实践中的复杂度

虽然最坏是指数级，但实际中现代 SAT 求解器（如 MiniSat, CryptoMiniSat）能解决数百万变量的工业实例！

原因：
- 实际问题有结构，不是最坏情况
- 聪明的剪枝（单元传播、冲突学习）
- 但仍然会遇到"硬"实例

### 相变现象（对于随机 3-SAT）

```
令 α = m/n（子句数/变量数）

  α < 4.27：几乎肯定可满足，而且容易找到解
  α ≈ 4.27：相变点！最难的实例在这里
  α > 4.27：几乎肯定不可满足

           难度
            ↑
            │       ╱╲
            │      ╱  ╲
            │     ╱    ╲
            │    ╱      ╲
            │   ╱        ╲
            │──╱──────────╲──────→ α
              4.27
            （相变点）
```

## 📝 总结

```
┌────────────────────────────────────────────────────┐
│  2-SAT vs 3-SAT                                    │
│  ────────────────────────────────────────────────  │
│                                                    │
│  2-SAT：每次决策只有一条路 → 可以"推导" → P        │
│  3-SAT：每次决策有多条路 → 需要"猜测" → NP-complete│
│                                                    │
│  关键差异：2个文字的"或"可以变成确定性蕴含          │
│           3个文字的"或"必须做非确定性选择           │
└────────────────────────────────────────────────────┘

┌────────────────────────────────────────────────────┐
│  3-SAT 复杂度一览                                   │
│  ────────────────────────────────────────────────  │
│                                                    │
│  验证：O(m) — 多项式时间 ✓                         │
│  求解：O(2ⁿ) 最坏 / O(1.307ⁿ) 最好已知             │
│                                                    │
│  NP-complete 意味着：                              │
│    • 不太可能有多项式算法（除非 P = NP）            │
│    • 所有 NP 问题都能归约到它                       │
│    • 是"最难"的 NP 问题之一                        │
│                                                    │
└────────────────────────────────────────────────────┘
```
